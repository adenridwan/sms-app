# Local-First Architecture

## Overview

Aplikasi mobile berjalan **sepenuhnya independen** tanpa ketergantungan backend. Backend bersifat **opsional** untuk sinkronisasi data.

## Flow Diagram

```
┌─────────────────────────────────────────────────────────────┐
│ 1. INSTALL & SETUP (No internet needed)                     │
│    └─→ Create local account (email, password)               │
│    └─→ Data stored in local SQLite                          │
└─────────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. USE APP OFFLINE                                          │
│    └─→ Login with local credentials                         │
│    └─→ Status: "Belum terhubung ke sekolah"                 │
│    └─→ Limited features (no classes/students)               │
└─────────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. CONNECT TO SCHOOL (One time, needs internet)             │
│    └─→ Admin generates QR in backend                        │
│    └─→ User scans QR → stores API URL + sync token          │
│    └─→ Press "Sync" → downloads classes & students          │
│    └─→ Status: "Terhubung ke: SMP Negeri 1"                 │
└─────────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 4. DAILY USE                                                │
│    └─→ Login locally (works offline)                        │
│    └─→ Record attendance (saved locally)                    │
│    └─→ Press "Sync" when online → push/pull data            │
└─────────────────────────────────────────────────────────────┘
```

## QR Code Content

```json
{
  "api": "https://smpn1.sch.id/api/v1",
  "token": "sync_token_abc123",
  "school": "SMP Negeri 1 Bandung"
}
```

- `api`: Backend API URL
- `token`: Sync token tied to specific backend user (generated by admin)
- `school`: School name for display

## Database Schema

### Local Accounts (independent)
```sql
CREATE TABLE local_accounts (
  id TEXT PRIMARY KEY,
  email TEXT UNIQUE NOT NULL,
  full_name TEXT NOT NULL,
  password_hash TEXT NOT NULL,  -- PBKDF2
  password_salt TEXT NOT NULL,
  created_at DATETIME,
  updated_at DATETIME
);
```

### Backend Connection (from QR)
```sql
CREATE TABLE backend_connection (
  id INTEGER PRIMARY KEY,  -- always 1, singleton
  api_url TEXT,
  sync_token TEXT,
  school_name TEXT,
  backend_user_id TEXT,    -- user ID on backend (from token)
  backend_user_name TEXT,  -- user name on backend
  connected_at DATETIME,
  last_sync_at DATETIME
);
```

## Account Relationship

```
┌─────────────────────┐         ┌─────────────────────┐
│ LOCAL ACCOUNT       │         │ BACKEND IDENTITY    │
│                     │         │                     │
│ email: any@mail.com │ ──────► │ Determined by token │
│ password: local     │  QR     │ Could be different  │
│                     │  scan   │ email on backend    │
└─────────────────────┘         └─────────────────────┘

Local account = "key to open app"
QR token = "key to sync with school"
```

## API Endpoints (Backend)

### Generate Sync Token (Admin)
```
POST /api/v1/devices/provision
{
  "user_id": "uuid-of-teacher",
  "expires_in": 86400  // 24 hours
}

Response:
{
  "token": "sync_token_abc123",
  "user_name": "Budi Santoso",
  "expires_at": "2024-01-16T10:00:00Z"
}
```

### Validate Token & Get User (Mobile)
```
POST /api/v1/devices/connect
{
  "token": "sync_token_abc123"
}

Response:
{
  "user_id": "uuid",
  "user_name": "Budi Santoso",
  "user_email": "budi@school.id",
  "school_name": "SMP Negeri 1",
  "permissions": ["attendance.record", ...]
}
```

### Sync Data (Mobile)
```
POST /api/v1/sync
Authorization: Bearer {sync_token}
{
  "last_sync": "2024-01-15T10:00:00Z",
  "push": {
    "attendance": [...]
  }
}

Response:
{
  "pull": {
    "classrooms": [...],
    "students": [...],
    "notifications": [...]
  },
  "sync_time": "2024-01-16T10:00:00Z"
}
```

## Security Considerations

1. **Local password**: PBKDF2 with 50,000 iterations
2. **Sync token**: JWT with expiry, tied to specific user
3. **Token revocation**: Backend can invalidate token
4. **Device limit**: Backend can limit devices per user
